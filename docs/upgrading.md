# 更新与回退

先确认正在使用的 Skill 名称、来源仓库和提交。保存当前安装目录及自己的修改，查阅 CHANGELOG.md；不要直接在安装目录中拉取不明来源代码，也不要合并覆盖旧包。

将指定版本安装到一个新的空目录，保留整个安装单元及许可。用自己的去敏任务确认入口、所需工具、交接材料和关键脚本可用；特别核对价格、功能、授权和结果状态。验证范围取决于当前任务，不把结构检查通过当业务效果通过。

关闭使用该目录的客户端，将旧目录移到备份位置，再把完整新单元放到原位置，重新加载客户端。不同时保留两个同名 Skill 供客户端发现。若不能正常使用，关闭客户端、移走新版、恢复原目录并重新加载；项目业务资料单独保存，不随技能目录迁移或删除。

合集 catalog.json 锁定各自提交：单仓 main 有更新，不代表合集已包含。更新合集版本应先在临时目录实际下载并验证五包，再记录新的版本与日期；旧验收记录作为历史保留，不能只改其 SHA。
